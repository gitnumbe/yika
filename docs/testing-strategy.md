# 测试策略（三层次测试）

> **核心立场**：**编译通过 ≠ 功能和业务逻辑正确。** 编译只保证语法和类型，业务闭环的正确性必须靠分层测试来验证。
> 本文件定义三层次测试的划分、职责、运行时机，以及如何用 pytest marker 分层执行。

---

## 1. 三层次划分

| 层 | marker | 名称 | 测什么 | 依赖 | 速度 |
|---|---|---|---|---|---|
| **L1** | `@pytest.mark.l1` | 单元测试 | 当前模块内部逻辑（纯函数、mock 外部依赖） | 无 DB、无网络 | 极快 |
| **L2** | `@pytest.mark.l2` | 关联回测 | 接口契约、权限、状态机流转（走 TestClient + DB） | 内存 SQLite | 中 |
| **L3** | `@pytest.mark.l3` | 业务闭环测试 | 跨模块的完整业务流（端到端） | 内存 SQLite | 中 |

---

## 2. 每层测什么（对应到本项目）

### L1 单元测试（当前功能模块）

**目标**：验证单个函数/模块的内部逻辑正确，隔离外部依赖。

本项目实例：
- `test_state_machine.py` — 状态机纯函数 `can_transition`（无 IO，纯逻辑）
- `test_llm.py` — LLM provider 请求格式（mock httpx，不发真实请求）
- `test_asr.py` — ASR provider 请求格式（mock httpx）

**特征**：`monkeypatch` 外部依赖，不碰数据库，跑得极快（<0.1s）。

### L2 关联回测（关联功能的回测）

**目标**：验证接口契约、权限边界、状态流转是否正确——即"改 A 是否破坏了依赖 A 的 B"。

本项目实例：
- `test_auth.py` — 注册/登录契约 + 密码校验
- `test_customers_projects.py` — 客户/项目 CRUD 契约
- `test_knowledge.py` — 知识库权限（技术写、讲师读）
- `test_requirements.py` — 需求接口 + 状态流转 + 角色权限
- `test_qa.py` — 答疑接口（命中/未命中/回流）
- `test_backup.py` — 备份导出权限（仅 admin）

**特征**：走 `TestClient` + 内存 SQLite，验证完整 HTTP 链路 + 鉴权。

### L3 业务闭环测试（核心业务闭环）

**目标**：验证**跨模块的完整业务流**是否跑得通——不是单个接口对，而是"从 A 走到 Z 的整个流程"对。

本项目实例（`test_business_flows.py`）：
- **需求全生命周期**：讲师提出 → 技术评审 → 可行 → 开发 → 交付（含终态不可再流转）
- **需求调整/重评闭环**：信息待补充 → 重提 → 不可行 → 重新评估 → 交付
- **答疑飞轮闭环**：讲师提问未命中 → 转技术 → 作答回流 → 再问命中
- **权限边界闭环**：讲师全程不能做技术的事（流转/写知识库/导出）

**特征**：一个测试函数跨多个接口、多个模块，验证业务闭环完整。

## 3. 运行时机（结合影响分析 + 变更预算）

| 场景 | 必跑哪层 | 说明 |
|---|---|---|
| 开发中（改单个模块） | **L1** | 改动后立即跑，快速反馈 |
| 改受控层（接口/状态机/权限/模型） | **L1 + L2** | 契约和权限可能被连带破坏 |
| 改冻结层（走决策变更流程） | **L1 + L2 + L3** | 全量回归，业务闭环不能断 |
| 提交前 / 合并前 | **L1 + L2 + L3** | 全量，确保没回归 |

**命令**：

```powershell
# 只跑某层
.\.venv\Scripts\python.exe -m pytest tests/ -m l1 -v   # 单元
.\.venv\Scripts\python.exe -m pytest tests/ -m l2 -v   # 关联回测
.\.venv\Scripts\python.exe -m pytest tests/ -m l3 -v   # 业务闭环

# 全量（提交前必跑）
.\.venv\Scripts\python.exe -m pytest tests/ -v
```

---

## 4. 新增测试的归属规则

写新测试时，先判断它属于哪层：

1. **测单个函数/纯逻辑/mock 外部依赖** → L1（不建 DB、不传 HTTP）
2. **测接口契约/权限/状态流转，走 TestClient** → L2
3. **测跨模块的完整业务流程（一个测试函数串起多个接口）** → L3

**判据**：如果这个测试的失败意味着"业务流程断了"而不是"某个函数错了"，它就是 L3。

---

## 5. 三层次与"编译通过 ≠ 正确"的关系

```
编译（tsc / python 语法）    → 保证：语法、类型对
L1 单元测试                  → 保证：每个模块内部逻辑对
L2 关联回测                  → 保证：模块之间接口/权限对
L3 业务闭环测试              → 保证：端到端业务流程对
```

**四者缺一不可**。编译过了只说明"代码能跑"，L3 过了才说明"业务真的对"。
