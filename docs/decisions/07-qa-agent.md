# 决策 07：答疑 agent 设计（关键词检索 + 回流）

**状态**：已采纳（MVP 阶段）
**日期**：2026-08-25

## 背景

痛点之一：讲师缺 AI 知识，频繁问技术人员。答疑 agent 的目标是：讲师提问 → 先自动答 → 答不出再转技术人员。

这需要两个能力：
1. **检索**：从知识库里找相关答案。
2. **回流**：技术人员答完，答案沉淀回知识库，下次能自动答。

## 决策

**MVP 用关键词重叠检索**（`_search_knowledge`：对知识条目标题+内容做字符集重叠打分，取最高分）。

答疑流程：
```
讲师提问 → 检索知识库 → 命中：直接答(带来源) → 结束
                        → 未命中：转"待答疑"队列 @技术人员
技术人员作答 → 问答对回流知识库（下次能自动答）
```

## 为什么这么设计

1. **MVP 阶段知识库小**，关键词重叠已经够用，无需上向量检索（过度设计）。YAGNI。
2. **回流闭环是核心价值**：技术人员的重复答疑会越来越少——这是"越用越厚"的飞轮，比检索算法本身更重要。
3. **转人工带上下文**：讲师的问题连同检索到的相关内容一起给技术，避免技术重复问。

## 备选方案（为何没选）

- **MVP 就上向量检索/RAG**：知识库还没几条数据，向量化是纯负担；等数据量大了再换，接口抽象已经留好。
- **不做回流**：答疑 agent 永远依赖技术人工答，没有复利，痛点不消失。

## 核心原则

**先跑通闭环，再优化精度；回流闭环的价值大于检索算法的精度。**

## 关联代码

- `backend/app/services/qa_service.py` — `_search_knowledge`（关键词检索）+ `answer`
- `backend/app/routers/qa.py` — `/qa/ask` + `/qa/{id}/answer`（作答时回流知识库）
- `backend/tests/test_qa.py` — 命中/未命中/回流三场景测试
