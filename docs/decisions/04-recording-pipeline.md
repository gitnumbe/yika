# 决策 04：录音流水线设计（去噪 + 不做三方说话人分离）

**状态**：已采纳（转写环节选型于 2026-09-01 变更，见 [[09-voice-local-stt-tts]]，决策本身不变）
**日期**：2026-08-25（变更 2026-09-01）

## 背景

录音 → 转写 → 笔记 → 需求，是系统的核心链路。录音发生在两个场景：内部沟通（答疑/学习）和客户需求探索。

关键问题：**要不要做"说话人分离"（区分讲师/技术/客户各自说了什么）？**

## 决策

**不做三方说话人分离。** 主链路是「小模型去噪 → 大模型分析」：

```
录音 → Qwen3-ASR-1.7B 转写（决策 09，原 FunASR 已变更）→ 小模型去噪(过滤废话) → 大模型整理笔记 → 大模型提炼需求
```

- **内部沟通场景**：纯去噪 + 分析，完全不区分人。
- **客户需求场景**：叠加「内部人 vs 客户」**二分类**（不是三方分离），用于标记"客户潜在需求线索" vs "内部结论/待办"。

## 为什么这么设计

1. **最终目的是提取信息，不是归因**。要的是"会议里有什么重要内容"，而不是"谁说了哪句话"。
2. **三方分离准确率低**。三人中文对话、抢话、噪音下，diarization 误差大，标错说话人会**误导**后续分析，弊大于利。
3. **二分类够用且准确率高**。"是不是客户在说话"远比"是讲师还是技术"好判断，且正好覆盖核心诉求——客户要什么 vs 内部结论。
4. **小模型去噪是成熟的两阶段流水线**：先用小模型/规则粗筛废话，大模型再做精加工，省钱又准。

## 备选方案（为何没选）

- **三方说话人分离**：准确率低，误差会污染需求提炼，违背"辅助手段服务于目的"的原则。
- **人工高亮引导**：最准但多一步人工，违背"省事"初衷。

## 核心原则

**辅助手段服务于目的；准确率低的手段宁可不用，除非它覆盖不可替代的诉求。**
