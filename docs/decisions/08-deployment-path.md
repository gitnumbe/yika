# 决策 08：部署路径（先内网电脑，后公司服务器）

**状态**：已采纳
**日期**：2026-08-25

## 背景

约束链：
- 公司内网 GPU 服务器（跑 Qwen3-27B）**没有部署权限**（暂时）。
- 但 Qwen3-27B 的**推理 API 有权限调用**（模型已部署好，能通过内网访问）。
- 数据希望最终多人协作，但要"成熟后"才申请权限迁服务器。

## 决策

**初期：后端跑在"公司内网一台普通电脑"上**（能访问内网 Qwen 的机器），本机多开（多账号多角色登录）模拟协作，不投入生产。
**成熟后：申请权限，把同一套后端搬到公司服务器**，换 IP 即可，代码零改动。

## 为什么这么设计

1. **避开"云服务器访问不到内网模型"的坑**。如果初期放小云服务器，云服务器够不着内网 Qwen，要么内网穿透（安全红线），要么临时切 DeepSeek（多一次切换）。
2. **内网普通电脑能访问内网 Qwen**，LLM 直接可用，数据全在内网，最顺、最快见效。
3. **数据模型从第一天多用户**（见决策 02），迁服务器只是换 IP，不是重构。

## 备选方案（为何没选）

- **初期就上小云服务器**：云访问不到内网 Qwen，需要临时用 DeepSeek API + 迁回时再切，多一个切换动作且数据出内网。
- **等权限下来再开发**：阻塞开发，违背"先设计好功能、成熟后再部署"的诉求。

## 核心原则

**架构按最终形态设计，部署位置可替换。** 部署地址是配置项，不是架构的一部分。

## 关联代码

- `backend/app/config.py` — `database_url` / `llm_base_url` 等全从 `.env` 读，换环境只改配置
- `backend/.env.example` — 部署配置模板
- `backend/app/database.py` — SQLite 起步（可换 Postgres）
