## 3. 【P8.1 走查发现】`Authorization` 头认证失效（只用 cookie 认证）
- **现象**：`backend/app/auth.py` `get_current_user(token: str = Header(None), ...)` —— `Header(None)` 默认以参数名 `token` 作为 header 名，
  读到的是名为 `token` 的 HTTP 头，**而非 `Authorization`**。
  实测：仅发 `Authorization: Bearer <token>`（无 cookie）→ 401「未登录」；应用实际只靠共享 Cookie `yika_access` 认证。
- **影响**：浏览器门户因前端 `withCredentials` 携带 cookie 而正常（功能未断）；但**纯 API 客户端（只发 Bearer 头）会被 401**。
  这与 auth.py docstring「priority header」及开发文档「请求 header 优先带 token」**不一致**。
- **建议**：改为 `Header(..., alias="Authorization")` 并剥离 `Bearer ` 前缀（header 优先、cookie 兜底）；补 header-only 单测。
- **状态**：P8.1 走查发现，因范围锁定未在 P8 修复，记为已知技术债。

- **建议**：在 `transition_requirement`（评审落痕处）与知识 review 处补写 `AuditLog`（action=req_review/req_deliver/knowledge_review，含 user/target/结论）。
- **状态**：P8.2 DoD 自检发现，因范围锁定未在 P8 修复。

## 5. 【P8.2 DoD 部署】alembic 迁移在 SQLite(dev) 不完整
- **现象**：`alembic upgrade head` 在 SQLite 上失败——P3.5 迁移 `4e4a29dd8a69` 用 `op.create_foreign_key(...)` 对 `knowledge.reviewer_id` 加外键，SQLite 不支持 ALTER 加约束（需 batch mode）。
- **影响**：开发库(SQLite)无法经 alembic 完整迁移（开发靠 `create_all` 建表，故 app 可用）；生产为 PostgreSQL16 支持 ALTER，Dockerfile 已装 `psycopg2-binary`，推测 PG 下可过（本机未起 PG 验证）。
- **建议**：迁移改 `batch_alter_table` 或对该 FK 用 PG-only 处理；或在部署文档注明"迁移以 PG 为准，dev 用 create_all"。
- **状态**：P8.2 DoD 自检发现，因范围锁定未在 P8 修复。
